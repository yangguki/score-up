## 1. 한 줄 정의

**SCORE UP은 종목별 공식/운영 룰을 적용해 경기를 진행하고, 스코어·선수·대진·파울을 한곳에서 관리하는 현장 경기 운영 앱이다.**

종이 용지, 메모장, 종목별 단발 스코어 앱을 대체하는 것이 아니라, **경기를 처음부터 끝까지 운영하는 데 꼭 필요한 도구**를 만드는 것이 목표다.

---

## 2. 배경과 문제

아마추어 리그, 동호회, 학교, 생활체육 대회에서는 경기 자체가 아니라 **운영**에서 시간이 많이 든다.

| 현재 방식 | 현장에서 생기는 문제 |
| --- | --- |
| 종이 스코어시트, 화이트보드 | 기록 누락, 정정 분쟁, 사진 공유로 끝나는 기록 |
| 종목별 단발 스코어 앱 | 선수·대진·대회와 연결되지 않음 |
| 엑셀 / 카톡 / 구글시트 | 대진과 결과가 분리되고, 실시간 반영이 어려움 |
| 심판·운영자 머릿속 룰 | 세트 점수, 연장, 파울 퇴장 기준이 사람마다 다름 |

핵심 문제는 스코어를 “세는 것”이 아니다.

1. **종목마다 이기는 방식이 다르다** — 누적 득점, 세트제, 이닝제, 시간제
2. **룰을 적용하지 않으면 기록이 경기가 되지 않는다** — 승리 조건, 교체, 파울, 카드, 서브권
3. **한 번의 대회는 여러 경기의 연속이다** — 선수 등록 → 대진 → 경기 → 결과 반영 → 다음 라운드
4. **제재는 종목에 따라 경기의 일부다** — 농구 파울 아웃, 축구 경고/퇴장, 배구 경고 등

SCORE UP은 이 네 가지를 하나의 운영 흐름으로 묶는다.

## 3. 비전과 목표

### 3.1 비전

누구나 현장에서, 종목에 맞는 룰로, 실수 없이 경기를 운영할 수 있게 한다.

### 3.2 제품 목표

| 구분 | 목표 |
| --- | --- |
| 현장성 | 경기 중 3초 안에 득점·파울·세트 종료를 처리할 수 있다 |
| 정확성 | 종목 룰에 따라 승리/종료/제재가 자동으로 판정된다 |
| 연속성 | 선수·팀·대진·경기 결과가 끊기지 않고 이어진다 |
| 확장성 | 새 종목은 “새로운 앱”이 아니라 “룰 프리셋”으로 추가된다 |

### 3.3 성공의 정의 (1차)

- 운영자가 **한 대회를 앱만으로** 선수 등록부터 결승까지 끝낸다
- 심판/기록원이 **종목 룰을 외우지 않아도** 세트 종료·승리·퇴장을 맞게 처리한다
- 경기가 끝난 뒤 **별도의 엑셀 정리 없이** 결과와 순위를 공유할 수 있다

## 4. 타겟 사용자

1차 타겟은 프로 연맹이 아니라, **직접 경기를 운영하는 사람**이다.

### 4.1 페르소나

| 페르소나 | 역할 | 핵심 니즈 |
| --- | --- | --- |
| 리그 운영자 | 동호회/생활체육 대회를 만든다 | 선수 등록, 대진 생성, 결과 집계, 공지 |
| 심판 / 기록원 | 코트·필드 옆에서 경기를 진행한다 | 빠른 스코어, 룰 자동 적용, 파울/카드, 실수 정정 |
| 감독 / 주장 | 출전 명단과 교체를 관리한다 | 로스터, 출전, 파울 누적, 세트별 라인업 |
| 선수 / 관중 | 진행 상황을 본다 | 현재 스코어, 다음 대진, 최종 순위 (1차에서는 조회 중심) |
| 모임장 | 동호회를 지속 운영한다 | 멤버, 정기 회차, 참석 투표, 그날 매칭 (제품 Phase 3) |
| 모임 멤버 | 이번 주 올지 표시한다 | 참석/불참, 내 전적·랭킹 (제품 Phase 3) |

### 4.2 우선 사용 맥락

- 주말 동호회 리그, 사내 대회, 학교 체육대회, 생활체육 토너먼트
- 태블릿 또는 큰 폰을 테이블에 두고 기록하는 환경
- 네트워크가 불안정한 체육관·운동장 (오프라인 기록 후 동기화 필요)

## 5. 핵심 가치

| 가치 | 설명 |
| --- | --- |
| 종목 룰이 앱의 중심이다 | 스코어 버튼만 있는 앱이 아니라, 승리 조건·세트·제재가 종목마다 다르게 동작한다 |
| 경기 운영의 최소 완결 세트 | 선수, 대진, 스코어, 파울이 한 서비스 안에 있다 |
| 현장에서 실수하지 않게 | 종료 조건, 퇴장, 세트 승리는 시스템이 제안하고 운영자가 확정한다 |
| 대회가 끊기지 않는다 | 한 경기 결과가 대진표와 순위에 바로 반영된다 |

차별점은 “더 예쁜 스코어보드”가 아니라 **종목 룰 엔진 + 대회 운영 연결**이다.

---

## 6. 서비스 원칙

1. **종목은 프리셋, 대회·회차는 운영 단위**  
   농구/배구 같은 종목 템플릿을 고르고, 그 위에 대회·리그·친선경기를 만든다. 같은 멤버가 반복되면 **모임**이 지속 단위가 되고, 그날은 **회차**다 (제품 Phase 3).
2. **룰은 기본값을 주되, 현장에서 조정 가능하게**  
   공식 룰을 기본으로 두고, 동호회용 변형(쿼터 시간, 세트 점수, 파울 기준)을 허용한다.
3. **기록은 되돌릴 수 있어야 한다**  
   오터치에 대비해 득점/파울/카드는 타임라인으로 남기고 취소할 수 있다.
4. **한 손·한 시선으로 조작**  
   경기 화면은 스코어와 핵심 액션만 남긴다. 설정은 경기 시작 전에 끝낸다.
5. **종목에 없는 기능은 보여주지 않는다**  
   축구에 개인 파울 5개 퇴장을 넣지 않고, 탁구에 카드 시스템을 강제하지 않는다.

## 7. 핵심 기능

서비스는 경기 운영 다섯 모듈에, 이후 **모임**을 지속 층으로 얹는다. 1차(제품 MVP)는 여전히 **대회 → 경기 → 기록**이다. 모임은 제품 Phase 3.

```text
[종목/룰 프리셋]
        ↓
[모임] (Phase 3) → 멤버 → 회차+참석 투표 → 매칭 → 경기 운영 → 전적/랭킹
        ↓
[대회/리그] → [선수·팀] → [대진표] → [경기 운영] → [결과/순위]
                              ↑          │
                              └──────────┘
                         결과 반영, 다음 라운드
```

모임 상세·참석 ≠ 출전·자동 매칭 범위: [모임 기획](./SCORE-UP-모임-기획.md).

### 7.1 종목 · 룰 엔진

경기를 시작하기 전에 종목과 룰을 확정한다.

| 기능 | 설명 | 우선순위 |
| --- | --- | --- |
| 종목 프리셋 | 농구, 배구, 축구, 탁구 등 종목별 기본 룰 세트 | MVP |
| 룰 커스터마이즈 | 세트 점수, 쿼터 수, 경기 시간, 파울 아웃 기준 등 조정 | MVP |
| 승리 조건 엔진 | 목표 점수, 세트 승리, 시간 종료, 연장, 타이브레이크 | MVP |
| 진행 단위 | 쿼터 / 세트 / 이닝 / 전후반 등 종목별 진행 단위 | MVP |
| 서브·공격권 | 배구/탁구/배드민턴 등 서브권 표시 및 교대 | MVP |
| 공식/동호회 모드 | 공식 룰과 생활체육 변형 룰을 구분해 저장 | Phase 2 |

**룰 엔진이 자동으로 판단하는 것**

- 세트/쿼터 종료 여부
- 경기 종료 및 승자
- 듀스, 듀스 후 2점 차, 타이브레이크 진입
- 개인/팀 파울 누적에 따른 보너스 또는 퇴장 가능 상태
- 경고 누적에 따른 퇴장 (축구 등)

운영자는 버튼 하나로 확정하거나, 예외 상황(기권, 몰수, 중단)을 선택한다.

### 7.2 경기 스코어 운영

현장의 메인 화면이다.

| 기능 | 설명 | 우선순위 |
| --- | --- | --- |

| 진행 상태 | 현재 세트·쿼터·남은 시간·서브권 | MVP |

### 7.5 파울 · 제재 관리

종목에 따라 켜지거나 꺼지는 모듈이다.

| 기능 | 설명 | 적용 예시 | 우선순위 |
| --- | --- | --- | --- |
| 개인 파울 누적 | 선수별 파울 수, 제한 도달 시 알림 | 농구 5/6파울 아웃 | MVP |
| 팀 파울 | 쿼터/하프 팀 파울, 보너스 상황 | 농구 보너스 자유투 | MVP |

### 7.7 모임 · 회차 · 참석 (제품 Phase 3)

동호회가 매주 같은 종목으로 모일 때의 층이다. 대회를 대체하지 않는다. 상세는 [모임 기획](./SCORE-UP-모임-기획.md).

| 기능 | 설명 | 우선순위 |
| --- | --- | --- |
| 종목별 모임 | 모임 1개 = 종목 1개. 멤버·정기 규칙 | Phase 3-A |
| 회차 | 날짜·장소가 있는 한 번의 모임 | Phase 3-A |
| 참석 투표 | 참석 / 불참 / 미정. 마감 후 운영자 확정 | Phase 3-A |
| 참석자 관리 | 투표 목록, 수동 처리, 게스트 | Phase 3-A |
| 전적 · 승률 · 랭킹 | 회차 `completed` 경기·멤버만. 대회·게스트 제외 | Phase 3-A |
| 팀 나누기 | 참석자 → 홈/어웨이 후 기존 보드 | Phase 3-A (수동) |
| 자동 매칭 | 인원·승률로 팀 제안, 운영자 확정 | Phase 3-B |
| 4v4 회차 | 인원 미달 시 출전 4. 운영자 확정. 3x3 없음 | Phase 3-B |
| 월 정기 패턴 | 매달 N번째 요일 또는 매달 D일(1~28). 회차 취소≠규칙 삭제 | Phase 3-B |
| 급수 시즌 | 초급/중급/상급. 운영자 지정. 기간=시즌 라벨. 대회 리그와 별개 | Phase 3-B |
| 결과 넣기 · 도전장 | 보드 없이 두 멤버 점수. 도전은 수락 후 결과 넣기. 사진·ELO 없음 | Phase 3-B |
| 배드민턴 모임 1차 | 참석·급수·한 판(단식/복식)·결과 넣기. 농구 5v5 복사 없음. 회비·멀티코트 순환 없음 | Phase 8 mock |
| 전략 분석 | 최근 경기 추이 등. 영상·샷차트 없음 | Phase 3-C (보류) |

**참석은 출전이 아니다.** 한 판 선발은 회차 포맷이다. 농구 기본 5+5(인원 미달 시 4+4). 배드민턴 모임 1차는 단식 1+1 또는 복식 2+2 (`docs/SCORE-UP-모임-기획.md` §21).

`내 모임`은 **종목마다 클럽을 따로** 운영한다. 한 모임에 농구+배드민턴을 섞지 않는다. 공통 운영(멤버·회차·투표·전적)은 재사용하고, 당일 편성·보드는 종목 프리셋이다.

| 층 | 내용 | 우선 |
| --- | --- | --- |
| 공통 | 모임=종목 1개, 멤버·역할·초대승인, 정기/번개 회차, 참석 투표, 게스트, 전적 | Phase 3 (일부 mock) |
| 종목 오버레이 | 회차 포맷(5v5, 단식/복식, 6v6…), 매칭 규칙, 기존 종목 보드 | mock: 농구·배구·풋살·탁구·배드민턴 |
| 넣지 않음 | 회비·정산, 채팅·앨범, GPS/QR 출석, 구장 예약·결제, 멀티코트 TV, 박스 승강 자동 | — |

종목 특화 요약: 농구=픽업 5v5/4v4. 배구=6v6·인원 미달 4v4·세트 보드. 탁구=한 판(단식/복식). 배드민턴=한 판(2차는 여러 판). 풋살=5v5/4v4·전후반 보드. 축구·야구·스쿼시 모임은 아직 없음. 상세는 [모임 기획 §22](./SCORE-UP-모임-기획.md).

게시판·채팅·앨범·회비는 넣지 않는다. 배드민턴 셔틀콕 정산·코트 대기 호출도 넣지 않는다.

## 8. 종목별 룰 적용 모델

모든 종목을 처음부터 만들지 않는다. 대신 **스코어링 유형**을 먼저 정의하고, 그 위에 종목 프리셋을 얹는다.

### 8.1 스코어링 유형

| 유형 | 이기는 방식 | 대표 종목 | 1차 지원 |
| --- | --- | --- | --- |
| 시간 + 누적 득점 | 시간이 끝나면 점수가 높은 쪽이 승 | 축구, 풋살, 농구(쿼터) | MVP |
| 세트 + 목표 점수 | 세트 점수와 세트 승수로 승패 결정 | 배구, 탁구, 배드민턴 | MVP |
| 이닝 / 기회 | 공격 기회 후 점수 비교 | 야구, 소프트볼 | Phase 2 |
| 홀 / 스트로크 | 누적 타수 또는 홀 승패 | 골프 | 이후 검토 |

### 8.2 MVP 종목 프리셋 (안)

세 종목으로 **서로 다른 룰 축**을 검증한다.

| 종목 | 검증하는 축 | 필수 룰 | 제재 |
| --- | --- | --- | --- |
| 농구 | 시간제 + 개인/팀 파울 | 쿼터, 2/3점, 자유투, 팀 파울 보너스 | 개인 파울 아웃, 팀 파울 |
| 배구 | 세트제 + 서브권 | 25점/15점, 2점 차, 세트 승수, 로테이션(선택) | 경고(2차) |
| 탁구 | 개인전 세트제 | 11점, 듀스, 서브 2개 교대, 세트 승수 | 거의 없음 |
| 축구 | 시간제 + 카드 | 전후반, 골, 추가시간(간단) | 경고, 퇴장 |

1차 구현 권장 순서: **농구 → 배구 → 탁구**.  
축구는 스코어 자체는 단순하지만 카드·출전 정지 때문에 대진/선수 모듈과 함께 2순위로 넣어도 된다.

### 8.3 종목 공통 데이터와 종목 고유 데이터

**공통**

- 대회, 팀/선수, 대진, 경기 상태, 이벤트 로그, 최종 승패

**종목 고유**

- 농구: 쿼터, 개인 파울, 팀 파울, 득점 유형
- 배구: 세트 점수, 서브권, 로테이션
- 탁구: 서브 카운트, 듀스
- 축구: 카드, 교체 횟수, 전후반 시간

이 분리가 있어야 이후 종목 추가가 “화면을 새로 그리는 일”이 아니라 “룰 프리셋을 추가하는 일”이 된다.

### 8.4 룰 커스터마이즈 예시

| 항목 | 공식 기본값 예시 | 동호회에서 자주 바꾸는 값 |
| --- | --- | --- |
| 농구 쿼터 | 10분 × 4 | 8분 × 4, 12분 × 2. 최소 2쿼터, 쿼터 분 조정 |
| 농구 작전타임 | 60초 | 30 / 45 / 60 / 90초 |
| 농구 파울 아웃 | 5개 | 6개, 제한 없음 |
| 배구 세트 | 3판 2선승, 25점 | 1세트 15점, 3판 2선승 |
| 탁구 | 5판 3선승, 11점 | 3판 2선승, 21점 |
| 축구 | 45분 × 2 | 20분 × 2, 30분 × 2 |

기본값을 제공하되, 대회 생성 시 “이 대회 룰”로 저장한다. 경기마다 즉흥적으로 바꾸면 분쟁이 생기므로, **변경은 경기 시작 전**으로 제한하는 것을 원칙으로 한다.

## 9. 주요 사용자 시나리오

### 시나리오 A. 주말 농구 토너먼트

1. 운영자가 종목 `농구`, 룰 `동호회 8분 쿼터 / 파울 6개`로 대회를 만든다
2. 8개 팀을 등록하고 선수 로스터를 넣는다
3. 8강 대진을 자동 생성한다
4. 심판이 첫 경기를 열고 선발을 확인한 뒤 스코어보드에서 **경기 시작**을 눌러 쿼터 타이머를 시작한다
5. 득점(2점/3점), 파울, 교체를 기록한다
6. 한 선수가 6파울에 도달하면 앱이 퇴장 가능 상태를 알리고, 출전을 막는다
7. 경기 종료 시 승자가 다음 라운드에 자동 올라간다
8. 결승까지 같은 방식으로 진행하고 우승팀을 확정한다

### 시나리오 B. 배구 리그 정규 라운드

1. 운영자가 6개 팀 리그를 만들고 승점제(승 3, 패 0 또는 세트 점수제)를 고른다
2. 라운드 로빈 대진이 생성된다
3. 기록원이 세트 점수와 서브권을 갱신한다
4. 24-24 듀스에서 2점 차가 날 때까지 세트가 끝나지 않는다
5. 경기 결과가 순위표에 반영된다

### 시나리오 C. 탁구 개인전

1. 선수 16명을 등록한다
2. 단식 토너먼트 대진을 만든다
3. 11점제, 서브 2개 교대로 경기를 진행한다
4. 선수 관리 외 파울 모듈은 화면에 노출하지 않는다
5. 대진표만으로 대회가 끝난다

### 시나리오 D. 예외 처리

- 상대 팀 미도착 → 몰수승
- 부상으로 경기 중단 → 중단 상태 저장 후 재개 또는 추후 처리
- 오터치 득점 → 타임라인에서 해당 이벤트 취소
- 항의/판정 번복 → 운영자 권한으로 결과 수정, 수정 이력 남김

### 시나리오 E. 주말 농구 모임 (제품 Phase 3)

1. 모임장이 종목 `농구`로 모임을 만든다
2. 멤버를 초대한다
3. 매주 토 14:00 정기 규칙을 두고, 이번 주 회차가 열린다
4. 멤버가 참석/불참/미정을 고른다
5. 마감 후 모임장이 참석자를 확인하고 팀을 나눈다 (이후 자동 매칭 제안)
6. 경기는 기존 농구 보드로 기록한다
7. 결과가 모임 전적·랭킹에 쌓인다

## 12. MVP 범위

### 12.1 MVP에 넣는 것

- 종목 프리셋 3개: 농구, 배구, 탁구
- 룰 커스터마이즈 (시간, 세트 점수, 파울 기준, 세트 승수)
- 선수/팀 등록, 경기별 출전 명단
- 토너먼트 대진 + 리그 순위표
- 경기 스코어, 이벤트 타임라인, 정정
- 농구 파울(개인/팀), 배구·탁구 서브권
- 경기 결과의 대진/순위 자동 반영
- 기권/몰수/중단
- 단일 운영자 기준의 로컬+계정 저장

### 12.2 MVP에서 빼는 것

- 실시간 관중용 웹 스코어보드
- 영상 하이라이트, 자동 통계 고급화 (리바운드, 어시스트 등)
- 결제, 참가비, 유니폼, 심판 배정 마켓
- 골프/야구 등 이질적 스코어링 종목
- 복잡한 더블 엘리미네이션, 스위스 시스템
- 소셜 피드, 선수 커뮤니티
- 공식 연맹 심판 자격 연동
- 모임·참석 투표·자동 매칭 (제품 Phase 3. 계정 필요)

### 12.3 MVP가 증명해야 하는 가설

1. 운영자는 종목 프리셋만으로 대회를 만들 수 있다
2. 기록원은 룰을 몰라도 세트 종료와 파울 아웃을 맞게 처리한다
3. 대진-경기-결과가 연결되어 엑셀 없이 대회가 끝난다
4. 새 종목 추가는 기존 모듈을 재사용하는 방식으로 가능하다

## 13. 로드맵 (안)

| 단계 | 기간 감각 | 초점 | 결과물 |
| --- | --- | --- | --- |
| Phase 0 | 현재 | 기획 합의 | 본 문서, 종목 우선순위, MVP 확정 |

```text
  - Session이 Match를 생성. 보드는 기존 Match
```

모든 스코어는 **현재 점수 숫자만 저장하지 않고**, 이벤트 로그를 기준으로 다시 계산할 수 있게 한다. 정정과 분쟁 대응을 위해서다.

## 15. 비기능 요구사항

| 영역 | 요구 |
| --- | --- |
| 조작 속도 | 득점/파울 입력은 즉시 반영. 경기 화면 전환 최소화 |
| 오프라인 | 진행 중 경기는 네트워크 없이도 기록되고, 복구 후 동기화 |
| 실수 복구 | 모든 입력은 취소 가능, 결과 확정 전후를 구분 |
| 가독성 | 실내 체육관, 햇빛 있는 운동장 모두에서 스코어가 크게 보여야 함 |
| 디바이스 | 1차는 모바일+태블릿. 경기 기록 스코어보드는 **가로만** (세로는 안내) |
| 권한 | 기록 중 실수로 대진이 바뀌지 않도록 경기 중 편집 범위를 제한 |
| 데이터 | 대회/경기 기록은 시즌이 지나도 조회 가능해야 함 |

## 17. 리스크

| 리스크 | 영향 | 대응 |
| --- | --- | --- |
| 종목을 너무 일찍 많이 넣음 | 룰 엔진이 얕아지고 현장 오류가 남 | MVP는 3종목으로 엔진을 먼저 검증 |
| 공식 룰과 동호회 룰 충돌 | “앱이 틀렸다”는 분쟁 | 대회 시작 전 룰 요약 화면을 고정 노출 |
| 현장 네트워크 불안정 | 기록 유실 | 로컬 우선 저장, 이벤트 단위 동기화 |
| 스코어 앱으로만 인식됨 | 대진/선수 모듈이 쓰이지 않음 | 친선경기 진입은 쉽되, 대회 흐름을 기본 경로로 둠 |
| 밴드 클론으로 인식됨 | 게시판만 쓰고 경기를 안 연다 | 피드 없이 참석→매칭→보드로 닫음 |
| 파울/판정 책임 | 앱이 심판을 대체하는 것처럼 보임 | 앱은 보조 판정, 최종 확정은 운영자/심판 |

## 18. 지금 결정이 필요한 사항

기획을 다음 단계로 넘기려면 아래를 먼저 정하는 것이 좋다.

1. **1차 종목 3개 확정** — 제안: 농구, 배구, 탁구
2. **1차 플랫폼** — 모바일 앱만 / 태블릿 우선 / 웹 포함
3. **1차 사용 단위** — 친선 단발 경기 vs 대회 운영. 둘 다 필요하지만 홈 진입점은 하나여야 한다
4. **계정 모델** — 로그인 필수 vs 기기 로컬 먼저
5. **공식 룰 준수 수준** — 생활체육 변형을 기본으로 둘지, 공식 룰을 기본으로 둘지
6. **오프라인 필수 여부** — MVP부터 넣을지, 온라인 전제로 빨리 검증할지
7. ~~모임 랭킹·게스트·탭·미정·가입·4v4·기록원~~ → 모임 기획 v0.4. 요약: 랭킹=회차·멤버, 탭 3개, 미정=매칭 제외, 가입=초대+승인, 기본=5v5·인원 미달 시 4v4(운영자 확정)·모임장=기록원
8. ~~배드민턴 모임 1차 넣을 것/빼는 것~~ → 모임 기획 v0.7 §21. 참석·급수·한 판. 회비·멀티코트 없음. Phase 8 mock
9. ~~종목별 클럽 운영을 모임에 넣을지~~ → **공통 층 + 종목 오버레이**. 배구·풋살·탁구 mock 열림. 회비·채팅 없음
