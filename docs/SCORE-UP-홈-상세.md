## 2. 직무

운영자가 홈에서 하는 일, 우선순위 순.

1. **이어 기록** — 진행 중·일시정지·확인 대기 경기를 보드로
2. **오늘 시작** — 오늘 배정·출전 확인 경기를 출전 명단 또는 보드로
3. **대회 이어서 준비** — 준비 중 대회(팀/대진 미완)를 개요로
4. **새 대회** — 대회 만들기 1단계
5. **친선** — 이름 두 칸 후 보드 (의도적으로 4보다 약하게)

하지 않는 일: 관중 피드, 하이라이트, 일정 캘린더, 종목 탐색, 홈 로그인 캐러셀.

실제 앱은 **브랜드 허브**. 진행 중/내 대회 카드 규칙은 V1과 같다.

```text

│ SCORE UP                    운영자│
│ 지금 할 일과 만들 일               │  ← 헤더 서브
│ 01 / 02 / 03 가치                 │
│ [농구] [배구] [탁구] … 8종목       │  ← 2열 모자이크, 모두 활성
│ [ 대회 만들기 ]                    │
│ [ 빠른 친선경기 ]                 │
│ 지금 할 일                        │
│ ┌─────────────────────────────┐ │
│ │ 농구 · 4강 · 오늘 14:00  [진행]│ │
│ │ 호랑이          24 - 18  독수리│ │
│ │ Q2 05:32 · 이어하기            │ │
│ └─────────────────────────────┘ │
│ 내 대회                           │

│ │ 주말 농구 토너먼트      [농구] │ │
```

### 3c. 화면 골격 (H9 Play · 비교)

시안과 같은 레이아웃. **잠금 아님.** 테니스·족구·기타 게임은 그리지 않고 제품 8종목으로 둔다.

```text
┌─────────────────────────────────┐
│ [H1] [H8] [H9]                  │
│ 지금 ‘업’ 하고 싶은         [○up]│
│ 스코어는?                        │
│ [배드민턴] [탁구]                │
│ [배구]     [농구]                │
│ [풋살]     [축구]                │
│ [스쿼시]   [야구]                │
│ [ 스포츠 ] [ 최근 활동 ]         │
└─────────────────────────────────┘
```

- 헤드라인: `지금 ‘업’ 하고 싶은 스코어는?` (‘업’ 민트)
- 우측 원형 민트 `up` 로고 → 설정
- 종목 탭: 블롭 카드. **세로=작은 2열**, **가로=화면 폭 4열×2줄**. 탭하면 빠른 친선 `/friendly?sport=`
- 최근 활동: 대회 만들기 · 친선 · 지금 할 일 · 내 대회 · 내 모임
- 앱 탭(홈/대회/모임/설정)은 유지. 스포츠/최근 활동은 홈 안 독

키트: `/kit/play`.

## 4. 영역 명세

### 4.1 헤더

| 요소 | 규칙 |
| --- | --- |
| 타이틀 | `SCORE UP` |
| 서브 | `지금 할 일과 만들 일` |
| 우측 | H1: `운영자` → 설정. H8: 원형 Up 로고 → 설정 (운영자 이름은 타이틀 아래). H9: 원형 민트 `up` → 설정 |
| 시안 전환 바 | **검수용.** H1 Arena / H8 Lift / H9 Play. 제품 기본은 H1. 설정에도 동일 스위치 |

검색, 알림종, 종목 칩은 그리지 않는다.

### 4.2 진행 중

**포함:** 아래를 **이 순서**로, 최대 5장.

1. 라이브류: `in_progress` / `paused` / `period_break` / `confirm_period_end` / `confirm_match_end`
2. 오늘 배정 + 아직 안 끝남: `scheduledLabel`에 `오늘` + `scheduled` | `lineup`
3. 친선이 위 조건이면 대회 경기와 **같은 목록**에 넣는다. 배지 `친선`

**제외:** `completed` / `forfeited` / `abandoned`. 어제 경기. 미래 날짜(`내일`, `8/29`).

5장 초과: 5장만 두고 행 `오늘 경기 더보기` → 해당 대회 경기 목록. 대회가 여러 개면 대회 탭.

섹션이 비었을 때:

| 조건 | 카피 |
| --- | --- |
| 앱에 대회/경기 없음 (진짜 빈 홈) | 섹션 제목은 유지. 본문은 4.5 빈 상태 한 덩어리만 |
| 대회는 있으나 오늘/라이브 없음 | `오늘 배정된 경기가 없습니다.` |

라이브와 오늘 대기가 같이 있으면 **라이브 카드를 먼저**, 대기 카드는 점수 없이 `vs`.

### 4.3 내 대회

- `status !== completed` 인 대회만. **2~5개**, 최신/진행 중 우선: `in_progress` → `prep`
- 6개 이상이면 5개 + `대회 모두 보기` → 대회 탭
- 종료 대회는 홈에 안 띄운다

한 줄 메타: `{형식} · {상태} · {날짜}`  
한 줄 다음 일: `다음 미진행 n경기` / `다음 미진행 없음`

`prep` 이고 경기 0이면 `다음 미진행 없음` 유지. 홈에서 ‘팀 등록’을 강제 히어로로 만들지 않는다. 탭하면 개요가 다음 할 일을 말한다.

### 4.4 하단이 아니라 종목 아래 CTA

| 버튼 | 스타일 | 도착 |
| --- | --- | --- |
| 대회 만들기 | primary, 동사 | `/competition/new` (1단계 종목) |
| 빠른 친선경기 | ghost | `/friendly` |

빈 홈에서도 **둘 다 보인다.** 친선을 더보기로 넣지 않는다.

### 4.5 빈 홈

대회 0 && 경기 0.

```text
SCORE UP                         운영자

지금 할 일
  첫 대회를 만들면 선수, 대진, 스코어가
  하나로 이어집니다.

내 대회
  (이 블록은 숨기거나, 같은 문장 반복하지 않는다)

[ 대회 만들기 ]
[ 빠른 친선경기 ]
```

구현: `내 대회` 섹션은 **빈 홈에서 숨긴다.** 진행 중 자리에 empty 카피 한 번만.

## 5. 카드 필드

### 5.1 경기 카드 (진행 중 섹션)

| 줄 | 라이브 (`in_progress` 등) | 오늘 대기 (`scheduled` / `lineup`) |
| --- | --- | --- |
| 1 좌 | `{종목} · {라운드} · {scheduledLabel}` | 동일 |
| 1 우 | 상태 필 `진행` / `일시정지` / `쿼터 사이` / `확인` | `대기` / `출전 확인` |
| 2 | 홈명 · **점수 크게** · 어웨이명 | 홈명 · `vs` · 어웨이명 (점수 0-0 금지) |
| 3 | `{Q# mm:ss} · 이어하기` | `{시간} · 경기 열기` 또는 `출전 확인` |

탭 목적지:

| 상태 | 이동 |
| --- | --- |
| `scheduled`, `lineup` | `/match/[id]/lineup` |
| 진행·정지·쿼터 사이·확인 | `/match/[id]/{sport}` 종목 보드 |
| `completed` 등 | 홈 목록에 없음. 들어오면 결과 |

홈 8종목 대회·친선 카드를 그린다. 친선은 라운드 자리에 `친선`.

점수 크기: 라이브만 **22pt** compact. 대기 카드는 팀명 15pt, `vs`는 muted. 카드 패딩 10. 홈/어웨이 라벨은 넣지 않는다.

### 5.2 대회 카드

| 줄 | 내용 |
| --- | --- |
| 1 | 대회명 + 종목 필 |
| 2 | `토너먼트` 또는 `리그` · `준비`/`진행` · 날짜 |
| 3 | `다음 미진행 n경기` |

탭 → `/competition/[id]` 개요.

시드는 주말 토너먼트(라이브 1 + 오늘 대기 2) + 사내 리그(준비).

| ID | 데이터 | 진행 중 | 내 대회 | CTA |

| S0 빈 | 없음 | empty 카피, 대회 섹션 숨김 | — | 둘 다 |
| S1 시드 (기본) | 라이브 1, 오늘 대기 2, 대회 2 | 카드 3 | 카드 2 | 둘 다 |
| S2 라이브만 | 진행 1, 오늘 대기 0 | 라이브 1 | 해당 대회 | 둘 다 |
| S3 오늘만 | 라이브 0, 오늘 대기 n | 대기 카드 n (점수 없음) | 있음 | 둘 다 |
| S4 준비만 | 대회 `prep`, 오늘 경기 없음 | `오늘 배정된 경기가 없습니다.` | 준비 대회 1+ | 둘 다 |
| S5 친선 라이브 | `isFriendly` 진행 중 | 친선 카드 포함 | 대회만 (친선은 대회 목록 아님) | 둘 다 |
| S6 다수 오늘 | 오늘 6+ | 5장 + 더보기 | 최대 5 | 둘 다 |
| S7 종료만 | 완료 대회만 | 빈 홈에 가깝게. 종료 대회 숨김 | 없음 → S0과 동일 empty | 둘 다 |

S0은 대회·경기가 실제로 없을 때만. 검수용 `빈 화면` 토글은 제거했다.

## 10. 구현 메모 (Frontend UX)

- 모델은 `buildHomeModel` 유지. 빈 홈에서 `competitions` 섹션 미렌더는 H1·H8·H9 최근 활동에 적용.
- 대기 카드 `0-0` 금지 — `MatchStackCard`가 라이브가 아니면 점수를 숨긴다.
- `isLiveLike`가 `scheduled`/`lineup`만 대기로 본다. `paused` 등은 점수 표시.
- 홈 버전: `useUiPrefsStore.homeVersion` (`h1` | `h8` | `h9`). 기본 `h1`. 키트 `/kit/arena` `/kit/lift` `/kit/play`.
- 시안 전환은 **앱 크롬 전체**(탭 바·헤더·`Screen`/`Card`/`Btn`). 보드는 Arena 셸 유지.

도메인 상태 키는 `packages/domain` 의 `MatchStatus`를 따른다. 본문 표의 `in_progress` 등은 기획 표현이고, 코드는 `in_progress` / `paused` / `period_break` / `confirm_period_end` / `confirm_match_end` 매핑을 `lib/home.ts`에 둔다.
