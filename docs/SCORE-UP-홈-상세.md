# SCORE UP 홈 상세

| 항목 | 내용 |
| --- | --- |
| 문서명 | 홈 화면 상세 와이어 |
| 버전 | v0.1 |
| 기준 | 화면 기획 v0.2 §4.1, 기획서 v0.2 |
| 담당 | Frontend UX (카피·상태 검수는 Basketball) |
| 디바이스 | 폰 세로 (대회 준비). 웹도 같은 레이아웃, 최대 폭 ~430 |
| 상태 | **H1 브랜드 허브 확정** (Ink & Court 비주얼). V2/V3·H2~H4는 비교용 |
| 기획 화면 | Cursor Canvas `home-brand-sport-hub.canvas.tsx` (폰 와이어 S0/S1) |

홈은 스코어보드가 아니다. **먼저 서비스가 무엇인지(브랜드·종목)를 보여 주고**, 이어서 30초 안에 ‘지금 기록할 경기’ 또는 ‘만들 일’을 고르게 한다.

### 제안: 브랜드 + 종목 허브 (2026-08-24)

스크롤 위쪽을 이렇게 바꾼다. 아래 “지금 할 일 / 내 대회 / CTA”는 유지.

1. **SCORE UP** (~28pt) + 한 줄 정의  
2. 가치 3줄 (프리셋 → 대진·스코어 → 룰 제안)  
3. **종목 그리드** — 농구·배구·탁구·축구·야구·배드민턴·스쿼시·풋살 등. **탭/대회 생성은 농구만**. 나머지는 `준비 중`  
4. Primary `농구로 대회 만들기` / Secondary `빠른 친선경기`  
5. 기존 진행 중 · 내 대회

앱에서 **H1~H4**로 비교 (V1~V3는 이전 시안 유지).

| ID | 이름 | 한 줄 |
| --- | --- | --- |
| H1 | 브랜드 허브 | 확정 후보 베이스 (와이어와 동일) |
| H2 | 라이브 우선 | 오늘 코트 · 라이브 핀 먼저 (GameChanger식) |
| H3 | 종목 모자이크 | 종목 카드가 히어로 |
| H4 | 이중 진입 | 대회 운영 vs 빠른 친선 두 문 (Scoreholio식) |

브라우저 비교: `docs/home-hub-versions.html`. 확정 후 하나만 남김.

## 2. 직무

운영자가 홈에서 하는 일, 우선순위 순.

1. **이어 기록** — 진행 중·일시정지·확인 대기 경기를 보드로
2. **오늘 시작** — 오늘 배정·출전 확인 경기를 출전 명단 또는 보드로
3. **대회 이어서 준비** — 준비 중 대회(팀/대진 미완)를 개요로
4. **새 대회** — 대회 만들기 1단계
5. **친선** — 이름 두 칸 후 보드 (의도적으로 4보다 약하게)

하지 않는 일: 관중 피드, 하이라이트, 일정 캘린더, 종목 탐색, 로그인.

## 4. 영역 명세

### 4.1 헤더

| 요소 | 규칙 |
| --- | --- |
| 타이틀 | `SCORE UP` |
| 서브 | `지금 할 일과 만들 일` |
| 우측 | `운영자` (MVP). 이후 계정명이 생기면 교체 |
| 시안 전환 바 | 검수 중에만. 채택 확정 후 제거 |

검색, 알림종, 종목 칩은 그리지 않는다.

### 4.2 진행 중

**포함:** 아래를 **이 순서**로, 최대 5장.

1. 라이브류: `in_progress` / `paused` / `period_break` / `confirm_period_end` / `confirm_match_end`
2. 오늘 배정 + 아직 안 끝남: `scheduledLabel`에 `오늘` + `scheduled` | `lineup`
3. 친선이 위 조건이면 대회 경기와 **같은 목록**에 넣는다. 배지 `친선`

**제외:** `completed` / `forfeited` / `abandoned`. 어제 경기. 미래 날짜(`내일`, `8/29`).

5장 초과: 5장만 두고 행 `오늘 경기 더보기` → 해당 대회 경기 목록. 대회가 여러 개면 대회 탭.

섹션이 비었을 때:

| 조건 | 카피 |
| --- | --- |
| 앱에 대회/경기 없음 (진짜 빈 홈) | 섹션 제목은 유지. 본문은 4.5 빈 상태 한 덩어리만 |
| 대회는 있으나 오늘/라이브 없음 | `오늘 배정된 경기가 없습니다.` |

라이브와 오늘 대기가 같이 있으면 **라이브 카드를 먼저**, 대기 카드는 점수 없이 `vs`.

### 4.3 내 대회

- `status !== completed` 인 대회만. **2~5개**, 최신/진행 중 우선: `in_progress` → `prep`
- 6개 이상이면 5개 + `대회 모두 보기` → 대회 탭
- 종료 대회는 홈에 안 띄운다

한 줄 메타: `{형식} · {상태} · {날짜}`  
한 줄 다음 일: `다음 미진행 n경기` / `다음 미진행 없음`

`prep` 이고 경기 0이면 `다음 미진행 없음` 유지. 홈에서 ‘팀 등록’을 강제 히어로로 만들지 않는다. 탭하면 개요가 다음 할 일을 말한다.

### 4.4 하단 CTA

| 버튼 | 스타일 | 도착 |
| --- | --- | --- |
| 대회 만들기 | primary, 동사 | `/competition/new` (1단계 종목) |
| 빠른 친선경기 | ghost | `/friendly` |

빈 홈에서도 **둘 다 보인다.** 친선을 더보기로 넣지 않는다 (화면 기획 오픈 이슈 4 → 이 문서에서 secondary 유지로 닫음).

### 4.5 빈 홈

대회 0 && 경기 0.

```text
SCORE UP                         운영자

진행 중
  첫 대회를 만들면 선수, 대진, 스코어가
  하나로 이어집니다.

내 대회
  (이 블록은 숨기거나, 같은 문장 반복하지 않는다)

[ 대회 만들기 ]
[ 빠른 친선경기 ]
```

구현: `내 대회` 섹션은 **빈 홈에서 숨긴다.** 진행 중 자리에 empty 카피 한 번만.

## 5. 카드 필드

### 5.1 경기 카드 (진행 중 섹션)

| 줄 | 라이브 (`in_progress` 등) | 오늘 대기 (`scheduled` / `lineup`) |
| --- | --- | --- |
| 1 좌 | `{종목} · {라운드} · {scheduledLabel}` | 동일 |
| 1 우 | 상태 필 `진행` / `일시정지` / `쿼터 사이` / `확인` | `대기` / `출전 확인` |
| 2 | 홈명 · **점수 크게** · 어웨이명 | 홈명 · `vs` · 어웨이명 (점수 0-0 금지) |
| 3 | `{Q# mm:ss} · 이어하기` | `{시간} · 경기 열기` 또는 `출전 확인` |

탭 목적지:

| 상태 | 이동 |
| --- | --- |
| `scheduled`, `lineup` | `/match/[id]/lineup` |
| 진행·정지·쿼터 사이·확인 | `/match/[id]/basketball` (농구) |
| `completed` 등 | 홈 목록에 없음. 들어오면 결과 |

농구 아니면 홈에 그리지 않는다 (1차). 친선은 라운드 자리에 `친선`.

점수 크기: 라이브만 28pt 전후. 대기 카드는 팀명 20pt, `vs`는 muted. V3에서 가져올 수 있는 것은 라이브 점수만 32pt까지.

### 5.2 대회 카드

| 줄 | 내용 |
| --- | --- |
| 1 | 대회명 + 종목 필 `농구` |
| 2 | `토너먼트` 또는 `리그` · `준비`/`진행` · 날짜 |
| 3 | `다음 미진행 n경기` |

탭 → `/competition/[id]` 개요.

## 6. 상태 매트릭스

시드는 주말 토너먼트(라이브 1 + 오늘 대기 2) + 사내 리그(준비).

| ID | 데이터 | 진행 중 | 내 대회 | CTA |
| --- | --- | --- | --- | --- |
| S0 빈 | 없음 | empty 카피, 대회 섹션 숨김 | — | 둘 다 |
| S1 시드 (기본) | 라이브 1, 오늘 대기 2, 대회 2 | 카드 3 | 카드 2 | 둘 다 |
| S2 라이브만 | 진행 1, 오늘 대기 0 | 라이브 1 | 해당 대회 | 둘 다 |

| S4 준비만 | 대회 `prep`, 오늘 경기 없음 | `오늘 배정된 경기가 없습니다.` | 준비 대회 1+ | 둘 다 |

| S7 종료만 | 완료 대회만 | 빈 홈에 가깝게. 종료 대회 숨김 | 없음 → S0과 동일 empty | 둘 다 |

앱 비교 토글 `빈 화면` = S0 미리보기. 검수 후 토글 제거.

## 10. 구현 메모 (Frontend UX)

- 모델은 `buildHomeModel` 유지. 빈 홈에서 `competitions` 섹션 미렌더는 V1만 적용해도 된다.
- 대기 카드 `0-0` 금지 — `MatchStackCard`가 라이브가 아니면 점수를 숨긴다 (현재 로직 유지).
- `isLiveLike`가 `scheduled`/`lineup`만 대기로 본다. `paused` 등은 점수 표시 — 유지.
- 채택 확정 시 `HomeVersionBar`와 V2/V3 파일 삭제, store의 `homeVersion` 제거.

도메인 상태 키는 `packages/domain` 의 `MatchStatus`를 따른다. 본문 표의 `in_progress` 등은 기획 표현이고, 코드는 `in_progress` / `paused` / `period_break` / `confirm_period_end` / `confirm_match_end` 매핑을 `lib/home.ts`에 둔다.

V3에서 가져올 수 있는 것: 라이브 카드 점수만 조금 더 크게 (28→32). 레이아웃은 V1.
