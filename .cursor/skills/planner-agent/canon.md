# SCORE UP 기획 캐논

학습용 요약. 날짜 기준 2026-08-26. 원문과 다르면 원문을 고친 뒤 여기도 고친다.

## 한 줄

SCORE UP은 종목 룰로 경기를 진행하고, 스코어·선수·대진·제재를 한곳에서 관리하는 **현장 경기 운영 앱**이다. 예쁜 점수판이 아니라 **룰 엔진 + 대회 운영 연결**이 차별점이다.

종이·단발 스코어 앱·엑셀을 “점수 세기”로 대체하지 않는다. 운영(룰 적용, 대회 연속, 제재)을 한 흐름으로 묶는다.

## 비전 · 목표 · 성공

비전: 현장에서 종목 룰로, 실수 없이 경기를 운영한다.

목표: 현장성(3초 입력) · 정확성(룰 판정) · 연속성(선수-대진-결과) · 확장성(종목=프리셋).

1차 성공: 한 대회를 앱만으로 결승까지. 기록원이 룰을 외우지 않아도 종료·퇴장 처리. 엑셀 없이 결과 공유.

## 타겟

1차: **직접 운영하는 사람** (프로 연맹 아님).

| 페르소나 | 1차 우선 |
| --- | --- |
| 리그 운영자 | 대회, 선수, 대진, 집계 |
| 심판/기록원 | 빠른 스코어, 룰 보조, 정정 |
| 감독/주장 | 로스터·교체 (보드 안) |
| 선수/관중 | 조회는 Phase 2 |
| 모임장·멤버 | 제품 Phase 3. 참석 투표·전적 |

맥락: 주말 동호회, 사내/학교 대회, 태블릿·큰 폰, 불안정한 네트워크(오프라인은 이 기기 persist. 동기화는 계정 때).

MVP 권한: **관리자=기록원 단독 운영**. 초대 UI는 오픈 이슈.

## 원칙

1. 종목은 프리셋, 대회·회차는 운영 단위. 반복 멤버는 **모임**(제품 Phase 3)
2. 공식 기본값 + 동호회 변형. **경기 시작 후 룰 변경 금지**
3. 기록은 타임라인으로 되돌린다
4. 한 손·한 시선. 설정은 시작 전
5. 종목에 없는 기능은 그리지 않는다
6. **시스템이 제안, 운영자가 확정** (`confirm_*`). 점수가 닿아도 바로 잠그지 않음
7. 앱은 심판을 대체하지 않는다
8. **참석 ≠ 출전.** 투표는 회차 상세에서만

## 모듈 (제품)

```text
[종목/룰 프리셋]
        ↓
[모임] (제품 Phase 3) → 멤버 → 회차+투표 → 매칭 → 경기 → 전적
        ↓
[대회/리그] → [선수·팀] → [대진표] → [경기 운영] → [결과/순위]
```

스코어링 유형: 시간+누적(농구) → 세트+목표(배구·탁구) → 이닝/홀은 이후.

공통 데이터: 대회, 팀/선수, 대진, 경기 상태, 이벤트 로그, 승패.  
종목 고유: 농구=쿼터·파울·득점유형. 배구=세트·서브·로테이션. 탁구=서브카운트·듀스.  
모임(이후): Club, Session, Attendance. **참석 ≠ 출전.**

## IA · 탭

탭: **홈 / 대회 / 설정**. 경기는 홈 카드 또는 대회에서 진입. 모임 전용 탭 없음. 제품 Phase 3에 홈 `내 모임` 섹션 + `/club/[id]` 스택.

```text
홈 → 진행 중 경기 / 내 대회 / 빠른 친선
대회 → 개요 / 참가 / 대진·순위 / 경기 목록 / 룰·설정
경기 → 출전 / 종목 보드 / 교체 / 타임라인 / 결과
```

준비=폰 세로. 보드=태블릿 가로. **폰 세로 보드는 MVP** — 세로·폭 820 미만이면 위아래 접힘. **가로는 항상 좌우**, 짧은 높이면 compact. **총점 최대 · 액션은 BoardKey/sm.**

## 핵심 흐름

**대회:** 홈 → 만들기 1~4(종목→룰→형식→정보) → 개요 → 참가 → 대진 → 출전 → 보드 → 결과 → 브래킷 반영 → 반복 → 우승. 만들기 와이어: `docs/SCORE-UP-대회-만들기-상세.md` (앱 5단계 팀은 명세 밖).

**친선:** 홈 → 빠른 친선 → 이름 두 칸 → (선수 있으면 출전) → 보드. 대진 없음. 대회 승격은 제품 Phase 2.

**기록원:** 진행 중/목록 → 출전 있으면 보드, 없으면 선발 후. 농구 시계는 보드의 경기 시작.

출전 [경기 시작] = `lineup`→`in_progress`, **시계는 안 돈다**. 보드 [경기 시작]이 1쿼터 시계.

## 홈 (H1 Arena)

홈은 점수판이 아니다. 브랜드·종목 다음, 30초 안에 ‘이어 기록’ 또는 ‘만들 일’.

- 헤더: `SCORE UP` / `지금 할 일과 만들 일` / `운영자`→설정
- 진행 중 최대 5: 라이브류 먼저(점수), 오늘 대기는 `vs`. 친선 포함, 라운드 자리 `친선`
- 내 대회 2~5, `completed` 제외. 빈 홈에서는 섹션 숨김
- 하단 고정이 아니라 종목 아래: **대회 만들기** / 빠른 친선경기
- 빈 카피: “첫 대회를 만들면 선수, 대진, 스코어가 하나로 이어집니다.”
- 카드: `scheduled`/`lineup`→출전, 진행류→종목 보드
- 홈 종목 타일: 8종목 활성. 모임은 농구만

시드 S1: 호랑이 24-18 독수리 + 오늘 대기 + 대회 2.

전역 토큰: `apps/mobile/theme/arena.ts`. 시안 바 제거됨 (H1 확정, H7 기각).

## 농구 제품 사실 (상세는 Basketball)

동호회 기본: 4Q×8분, 연장 3분, +2/+3/+1, 개인 아웃 6, 팀 파울 보너스 5번째, T/O 팀당 2·기본 60초, 출전 5, 샷클락 없음, 몰수 20-0. 토너먼트+연장 없음은 생성에서 막기.

보드에 둘 것: 총점, 쿼터, 시계, 이번 쿼터 팀 파울, 보너스 힌트, 최근 이벤트 1~3, 실행 취소, 일시정지. 서브권/세트/듀스 **금지**.

몰수·경기종료는 더보기. 실행 취소는 하단 고정.

## 공통 경기 상태

`scheduled` → `lineup` → `in_progress` ↔ `paused` → `confirm_period_end` / `confirm_match_end` → `completed`  
예외: `forfeited`, `abandoned`, `period_break`

이벤트: `point` `foul` `timeout` `substitution` `serve_change` `sanction` `period_end` `match_end` `revoke`  
스코어는 이벤트 재생으로 재계산 가능하게. mock은 스냅샷 직접 변경 + 타임라인용 이벤트 배열.

## 지금 구현 진도 (작업계획 = 진도 기준)

구현 **Phase 6**. 홈 8종목 대회·친선 mock + 이 기기 로그인 + 농구 모임.

**된 것:** 농구 수직 슬라이스 + Phase 5 엔진 + 리그 순위(승3/패0). Phase 6: 배구·탁구 mock 보드, persist, 텍스트 복사, 대회·친선 생성, **이 기기 이름 로그인, 모임·회차·참석 투표**, 배구 로테이션 표시·카드 메모, 탁구 복식 이름, **배드민턴·스쿼시 랠리 보드**, **축구·풋살 전후반 보드, 야구 이닝 보드**. 농구 시계는 보드를 떠나면 자동 pause. 폰 세로 스코어는 MVP.

**아직:** 실시간 공유 링크·이미지(API). 실서버 계정. 태블릿 실물 검수. 홈 A/B/C 제품 잠금(나중에).

다음 즉시: **구현 Phase 7** — 모임 3-B 자동 매칭 제안(농구 5v5). 기간형 급수 리그·도전은 그다음.

## 제품 MVP vs 지금 안 함

제품 MVP(기획서, 나중): 3종목, 룰 커스텀, 선수/대진/스코어/파울, 토너먼트+리그, 몰수/중단, 로컬+계정.

**이번 수직 슬라이스에서 안 함:** 실서버, 샷클락, 관중 보드, 이미지/링크 공유, 리그 승점 세부, 조별+결선, 웹 마케팅 페이지, **자동 매칭**.

리그 승점 MVP 고정안: **승 3 / 패 0**. 배구 세트 승점제는 제품 Phase 2.

## 명시적 리스크 (기획 시 기억)

종목 조기 남발, 공식 vs 동호회 분쟁(시작 전 룰 요약), 네트워크, 스코어 앱으로만 인식(친선 쉽게 하되 대회가 기본 경로), 밴드 클론(피드 없이 참석→보드), 앱이 심판처럼 보이는 카피.
