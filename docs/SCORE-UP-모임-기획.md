## 1. 한 줄

**모임**은 같은 종목을 반복해서 하는 사람들의 지속 단위다. **회차**는 그날의 모임이고, 참석 투표로 인원을 모은 뒤 경기를 연다. 대회(토너먼트/리그)를 대체하지 않고, 그 위에 얹는다.

---

## 2. 왜 필요한지

지금 제품은 **한 대회를 끝까지 운영**하는 도구다. 동호회 현장의 더 흔한 패턴은 대회가 아니라 **매주 같은 멤버가 오고, 온 사람으로 팀을 나누고, 친선을 여러 판 치는 것**이다.

| 지금 (대회) | 빠진 것 (밴드에서 하던 일) |
| --- | --- |
| 참가 팀/선수를 운영자가 등록 | 멤버가 스스로 참석/불참을 표시 |
| 대진은 시드·브래킷 | 온 사람 기준으로 그날 팀 나누기 |
| 결과는 그 대회 순위에만 | 시즌처럼 쌓이는 승률·랭킹 |
| 빠른 친선은 이름 두 칸, 멤버 없음 | 반복 일정과 출석 이력이 없음 |

핵심 문제는 스코어가 아니다. **누가 오는지 모으고, 온 사람으로 경기를 만들고, 그 결과가 모임에 남는 것**이다.

## 3. 밴드와 SCORE UP

| | 밴드 | SCORE UP 모임 |
| --- | --- | --- |
| 지속 단위 | 그룹 | **모임** (종목 1개) |
| 날짜 | 일정 + 참석 투표 | **회차** + 참석 투표 |
| 사람 | 멤버 | **모임 멤버** (선수와 연결) |
| 가져오지 않음 | 게시글, 댓글, 채팅, 사진첩, 출석 스티커 | — |
| SCORE UP만 | — | 룰 보드, 매칭 제안, 전적·승률·랭킹 |

모임이 밴드 클론이 되면 기획서 리스크(스코어 앱으로만 인식)의 반대가 된다. **피드 없이 경기 운영으로 닫는 모임**이 목표다.

## 4. 용어 (기존과 섞지 말 것)

| 용어 | 의미 | 아닌 것 |
| --- | --- | --- |
| 모임 (`Club`) | 종목 1개의 지속 그룹 | 대회, 팀 |
| 멤버 | 모임에 속한 사람 | 그날 참석자, 경기 선발 |
| 회차 (`Session`) | 날짜가 있는 한 번의 모임 | 경기(`Match`) |
| 참석 | 그 회차에 온다고 표시·확정된 상태 | 출전(선발 n명. 기본 5, 4v4면 4) |
| 출전 | 한 경기의 선발·벤치 | 참석 |
| 매칭 | 참석자를 홈/어웨이(또는 코트)로 나누는 제안 | 토너먼트 브래킷 |
| 대회 | 토너먼트/리그. 모임이 열 수도 있음 | 회차 |
| 정기 규칙 | 매주 또는 매달 반복으로 회차를 만드는 규칙. 모임당 1개 | 한 회차의 투표, 공휴일 달력 |

카피: `참석` / `불참` / `미정`. `출석체크`, `RSVP`, `게임 시작`은 쓰지 않는다.

## 5. 잠긴 결정

| 결정 | 선택 | 이유 |
| --- | --- | --- |
| 구현 시점 | **이 기기 이름 이후.** Cognito·API는 없음. mock 모임 1차 구현됨 | 투표는 ‘누구인지’가 필요 |
| 대회와의 관계 | 모임 ⊃ 회차 ⊃ 경기. 대회는 모임이 **열 수 있는** 다른 형식 | 브래킷 대회와 주말 픽업을 한 화면에 섞지 않음 |
| 종목 | 모임 1개 = 종목 1개. **지금 그리는 모임은 농구 + 배드민턴 1차.** 배구/탁구 모임 없음 | 기획서·작업계획의 1차 종목과 같음 |
| 배드민턴 모임 1차 | 참석·급수·한 판(단식 1+1 / 복식 2+2)·결과 넣기. 농구 5v5 복사 없음. 회비·멀티코트 순환 없음 | 총무의 명부·전적. 민턴인 클론 아님 (2026-08-27) |
| 참석 vs 출전 | 반드시 분리. 농구 한 판은 5+5 또는 4+4. 배드민턴 한 판은 §21 단식/복식 | 종목 보드 출전 수를 깨지 않음 |
| 매칭 | 시스템이 제안, 운영자가 확정 | 종료 팝업과 같은 원칙 |
| 전적/승률/랭킹 | **확정된 경기 결과에서만 계산.** 손으로 승률을 고치지 않음 | 분쟁 방지 |
| 전략 분석 | 모임 1차에 **없음** | 정의가 없고, 기획서도 고급 스탯을 MVP에서 뺌 |
| 소셜 | 게시판·채팅·앨범·회비 **없음** | 밴드가 아님 |
| 모임 랭킹 범위 | **회차에서 끝난 경기만.** 대회·친선은 넣지 않음 | 브래킷 성적과 픽업 승률을 섞지 않음 (2026-08-26) |
| 게스트 | 회차 명단에 **이름만**. 계정·랭킹·승률 없음 | 한 번 온 사람이 시즌 순위를 밀지 않게 (2026-08-26) |
| 모임 진입 | 탭은 **홈 / 대회 / 설정** 유지. 홈에 `내 모임` 섹션 + 모임 스택 라우트 | 4번째 탭은 현장 기록 CTA를 가림 (2026-08-26) |
| 미정(`maybe`) | 매칭 후보 **기본 제외.** 운영자가 `참석`으로 바꾼 사람만 들어감 | 앱이 ‘온다’고 단정하지 않음 (2026-08-26) |
| 가입 | **초대 링크 + 모임장 승인.** 1차는 전 모임 동일 | 링크 즉시가입은 게스트·랭킹이 섞임 (2026-08-26) |
| 인원 미달 포맷 | 기본 **5v5.** 10명 미만이면 5v5 잠금. **8~9명이면 운영자가 4대4로 나누기.** 8명 미만은 4v4도 잠금. 자동 전환 없음. 3x3 없음 | 출전 수는 Match.rules.starters. 대회 프리셋 5는 유지 (2026-08-27) |
| 기록원 | 모임 1차 **지정 UI 없음. 모임장=기록원** (운영 역할도 기록 가능). 멤버 지정은 대회 기록원 초대와 같이 | 권한 두 벌 방지 (2026-08-26) |

## 6. 기능 분해 (요청 → 제품)

요청 1(참석)과 2(모임)는 모듈이 두 개가 아니다. **모임 안에 회차 투표가 있다.**

### 6.1 모임 1차 (제품 Phase 3-A, 계정 다음)

| 요청 | 제품 기능 | 화면 |
| --- | --- | --- |
| 종목별 모임 | 모임 만들기 (종목, 이름, 장소 기본값) | 모임 만들기 |
| 멤버 관리 | 추가·내보내기, 역할(모임장/운영/멤버) | 멤버 |
| 참석 날짜 | 회차 단발 + **주 1회** + **월 정기**(N번째 요일 / D일) | 회차 만들기, 설정 |
| 참석 투표 | 참석 / 불참 / 미정. 마감 시각 | 회차 상세 |
| 참석자 관리 | 투표 목록, 운영자가 수동 참석 처리, 게스트 1차 가능 | 회차 상세 |
| 전적 | 회차 경기 + 급수 경기 목록 | 전적 |
| 승률·랭킹 | 승/패/승률/경기 수. 시즌 구간 1개. **급수별 표** (회차+급수 경기) | 랭킹 |

수동 매칭: 참석자 목록에서 홈/어웨이(또는 A/B)를 고른 뒤 **기존 출전 → 농구 보드**로 간다. 1차에서도 경기는 새 보드를 만들지 않는다.

### 6.2 모임 2차 (제품 Phase 3-B)

| 요청 | 제품 기능 |
| --- | --- |
| 자동 매칭 | 참석 인원·포맷(5v5/4v4)으로 팀 제안. 승률 밸런스 옵션. **5v5·4v4 제안 mock.** 코트 수는 1 |
| 4v4 회차 | 인원 미달(8~9명) 시 운영자가 출전 4 확정. 3x3는 안 함 |
| 월 정기 | 매달 N번째 요일, 또는 매달 D일(1~28). 특정 회차만 취소(규칙은 남음). 공휴일 자동 스킵 없음 |
| 급수 시즌 | 초급/중급/상급. 운영자 지정. 기간=시즌 라벨. ELO·자동 승급 없음 |
| 결과 넣기 | 보드 없이 두 멤버 + 점수. 사진 없음 |
| 도전장 | 보내기 → 수락/거절. 수락 후 결과 넣기. 같은 급수 또는 한 칸. 새 보드 없음 |
| 홈 연결 | 오늘/다음 회차 투표 카드를 홈 ‘지금 할 일’에 |
| 노쇼 | 참석인데 미도착 → 전적 제외, 운영자 표시 |
| 알림 | 투표 리마인드, 마감 임박 (계정·푸시 전제) |

### 6.3 이후 (제품 Phase 3-C / 넣지 않음)

| 요청 | 처리 |
| --- | --- |
| 전략 분석 | **보류.** 넣을 거면 별도 절: 최근 n경기 득점·파울 추이 정도. 영상·샷차트·플레이북 없음 |
| 멀티 종목 한 모임 | 안 함. 종목마다 모임 |
| 밴드/카톡 연동 | 안 함 |
| 회비·정산 | 요청 없음. 안 함. 배드민턴 셔틀콕 1/n·게스트비·미납 독촉도 여기 |
| 멀티코트 순환 | 안 함. 코트 대기 호출, 남복/여복/혼복 자동, A~D조 매칭은 민턴인 영역. §21 |
| 체육관 대관·결제 | 안 함 |

## 7. 기존 흐름과의 연결

```text
[종목 프리셋]
      ↓
[모임]──멤버
   │
   ├─ 회차 (날짜 + 투표) ── 참석 확정 ── 매칭(제안→확정) ── Match ── 출전 ── 보드 ── 결과 ── 모임 전적
   │
   └─ 대회 (기존 4단계) ── 참가 팀/선수(멤버에서 고를 수 있음) ── 대진 ── Match … ── 대회 순위
                                                                      │
빠른 친선 (모임 없음, 이름 두 칸) ─────────────────────────────────────┘
```

- 회차 경기와 대회 경기는 **같은 Match·같은 보드**다. 출처만 `sessionId` vs `competitionId`가 다르다.
- 모임 랭킹: **이 모임 회차의 `completed` Match만.** 대회·친선·다른 모임은 제외.
- 친선은 유지한다. 모임 없는 당일 픽업용. 모임 회차가 생기면 멤버 있는 픽업은 회차로 간다.

### 7.1 반드시 필요한 앞단 (요청에 없었지만 흐름상 필수)

계정 없이 투표·멤버·승률이 성립하지 않는다. 모임 구현 전에 아래가 닫혀 있어야 한다.

| 공백 | 왜 필요한지 |
| --- | --- |
| 계정(로그인) | 투표 주체, 멤버 식별 |
| 초대/가입 | **초대 링크 + 모임장 승인.** 즉시 가입 없음 (1차) |
| 선수 프로필 연결 | 멤버 = 계정 (+ 등번호). 대회 로스터와 같은 사람을 가리켜야 전적이 쌓임 |
| 장소 | 회차마다 체육관. 없으면 ‘언제’만 있고 ‘어디’가 없음 |
| 투표 마감 | 마감 전 변경 가능. 마감 후는 운영자만 수정 |
| 최소 인원 | 5v5는 후보 10명. 4v4는 후보 8명. 미달이면 해당 포맷 잠금 + 게스트 안내 |
| 회차 상태 | 아래 8장. 없으면 투표와 경기가 동시에 열린다 |
| 매칭 후 불참 | 확정 뒤 빠지면 재매칭 제안. 이미 시작된 Match는 기존 몰수/중단 |

### 7.2 요청에 있었으나 1차에 넣지 않는 것

자동 매칭·전략 분석은 전적 데이터가 쌓인 뒤에야 의미가 있다. 1차는 **투표 → 수동 팀 → 보드 → 전적 숫자**까지.

## 8. 회차 상태

시스템이 제안하고 운영자가 확정한다.

| 상태 | 의미 | 멤버 | 운영 |
| --- | --- | --- | --- |
| `draft` | 날짜만 있음. 투표 전 | 안 보임 가능 | 날짜·장소·정기 여부 수정 |
| `voting` | 참석 투표 중 | 참석/불참/미정 | 마감 시각, 수동 참석 |
| `confirming` | 마감됨. 인원 확정 중 | 보기·운영자에게 문의 | 게스트, 미투표 처리, 매칭 |
| `matched` | 팀(경기) 확정. 아직 팁오프 전 | 내 팀 확인 | 출전 화면으로 |
| `in_play` | 이 회차의 경기 중 1개라도 진행류 | 조회 | 보드 (기존) |
| `completed` | 회차 종료. 전적 반영 | 결과·랭킹 | 정정은 관리자 |
| `cancelled` | 미달·우천 등 | 안내 | 전적 없음 |

투표 값: `going` / `not_going` / `maybe` / `none`.  
매칭 후보 = `going` + 운영자가 넣은 게스트만. **`maybe`는 넣지 않는다.** 마감 후 `미정`→`참석`은 **운영자만**. 본인은 마감 후 변경 불가.

## 9. 핵심 사용자 흐름

### 9.1 모임을 만들고 첫 회차까지

```text
홈 또는 설정
 → 모임 만들기 (종목 농구, 이름, 기본 장소)
 → 멤버 초대
 → 회차 만들기 (단발 / 매주 / 매달)
 → 상태 voting
 → 멤버 투표
 → 마감 → confirming
 → 참석자 확인 (미투표 제외 또는 수동 추가)
 → 매칭 (1차: 수동 양팀 / 2차: 제안 후 확정)
 → 경기 카드들 생성 (Match)
 → 출전 명단 → 보드 → 결과
 → 모임 전적·랭킹 갱신
```

### 9.2 멤버가 참석만 하는 날

```text
홈 (이후: 오늘 회차 카드) 또는 모임 → 다가오는 회차
 → 참석 / 불참 / 미정
 → (마감 전) 변경
 → 매칭 후 내 팀 확인
 → 경기 시작 시각에 보드가 아니라 대기. 기록은 운영/기록원
```

멤버 전원에게 보드를 열지 않는다. 모임 1차 기록은 **모임장(및 운영 역할)** 만. 멤버를 기록원으로 지정하는 UI는 없다.

### 9.3 정기 모임 (월·주)

```text
정기 규칙: 매주 토 14:00  /  매달 첫째 토 14:00  /  매달 15일 14:00
 → 시스템이 앞 8회 회차 초안 (주=8주, 월=8개월)
 → 각 회차는 독립 투표
 → 한 회차만 취소해도 규칙은 남음
```

모임당 규칙 **1개**. 이미 같은 날짜의 미취소 회차가 있으면 건너뛴다.

| 종류 | 입력 | 초안 |
| --- | --- | --- |
| 매주 | 시작 날짜의 요일 + 시각 | 그 날짜부터 7일 간격 8회 |
| 매달 N번째 요일 | 첫째/둘째/셋째/넷째/마지막 + 요일 + 시각 | 시작일 이후 8회 |
| 매달 D일 | 일자 1~28 + 시각 | 시작일 이후 8회. 29~31 없음 |

설정에서 규칙을 고쳐도 **이미 만든 회차는 그대로**다. 새 초안은 회차 만들기에서만.

쓰지 않음: 공휴일 자동 스킵, 규칙 여러 개, 무한 생성, 푸시.

### 9.4 예외

| 상황 | 동작 |
| --- | --- |
| 마감 시 참석 7명 | 5v5·4v4 모두 잠금. “4대4는 참석 8명이 필요합니다. 게스트를 추가하세요.” |
| 마감 시 참석 8~9명 | 5v5 잠금. **4대4로 나누기** 활성. 9명이면 4+4+대기 1 |
| 마감 시 참석 10명 이상 | 5v5만. 4v4 버튼 없음 (인원 미달 슬라이스) |
| 참석 12명, 코트 1 | 10명 출전 + 2명 대기(로테이션). 대기만 표시, 자동 로테이션 없음 |
| 매칭 후 1명 불참 | `matched`에서 재제안. 이미 `in_progress`인 Match는 기존 중단/몰수 |
| 게스트 | 이름만 명단. **랭킹·승률 없음.** 보드 출전은 가능 |
| 운영자가 미투표자를 참석 처리 | 가능. 타임라인에 남김 |
| 회차와 대회가 같은 날 | 다른 객체. 홈 카드는 둘 다 ‘진행/오늘’로 보일 수 있음 |

## 10. 정보 구조 (예약)

구현 Phase 3 탭(홈 / 대회 / 설정)은 **유지한다. 모임 전용 탭을 만들지 않는다.** 제품 Phase 3-A에서 홈에 `내 모임` 섹션을 넣고, 상세는 스택(`/club/[id]` 등)으로 연다. 그때까지 이 트리를 그리지 않는다.

```text
앱
├─ 홈
│   ├─ 진행 중 경기     ← 이후: 오늘 회차 투표 카드 가능. 라운드 자리 `회차`
│   ├─ 내 대회
│   ├─ 내 모임          ← 제품 Phase 3-A. 탭 아님
│   └─ 빠른 친선경기
├─ 대회                ← 기존
├─ (스택) 모임
│   ├─ 개요 (종목, 다음 회차, 멤버 수)
│   ├─ 회차 목록 / 회차 상세 (투표, 참석자, 매칭, 그날 경기)
│   ├─ 멤버
│   ├─ 랭킹 / 전적      ← 회차 경기만, 게스트 행 없음
│   ├─ 정기 규칙
│   └─ 설정 (가입 방식, 시즌 구간, 기본 룰)
└─ 설정
탭: 홈 / 대회 / 설정
```

디바이스: 모임·투표·멤버는 **폰 세로**. 매칭 후 보드는 기존처럼 태블릿 가로.

## 12. 자동 매칭 (2차, 농구)

구현 Phase 7에서 **5v5 제안**과 **4v4 회차**를 넣었다. 확정은 운영자. 시스템이 포맷을 바꾸지 않는다.

| 입력 | 기본 |
| --- | --- |
| 포맷 | 회차 `format`: `5v5`(기본) / `4v4`(인원 미달 시 운영자 선택) |
| 코트 | 1 |
| 후보 | `going` (+ 운영자가 넣은 게스트) |
| 밸런스 | 꺼짐=무작위 양팀 / 켜짐=시즌 승률 스네이크 |
| 출전 | 5v5 → 팀당 5 · 4v4 → 팀당 4. `Match.rules.starters`에 기록 |

규칙

- 후보 < 8: 5v5·4v4 제안 불가. 안내만
- 후보 8~9: 5v5 불가. 운영자가 **4대4로 나누기**를 누르면 `format=4v4`로 split. 8명=4+4, 9명=4+4+대기 1
- 후보 = 10: 5v5 두 팀. 4v4 버튼 없음
- 후보 > 10: 10명 출전 + 나머지 대기. 대기 로테이션 자동은 3차
- 화면: 팀 나누기에서 **자동 제안** / **승률 밸런스** → 수정 → **매칭 확정**. 출전 칸 수는 회차 포맷
- 확정 시 Match 1개 생성 (홈=A, 어웨이=B, `sessionId`). 4v4면 `starters: 4`. 기존 출전 명단·농구 보드 재사용
- 경기 시작 후 포맷 변경 없음. 바꾸려면 다시 나누기 (팁오프 전만)

배구/탁구 매칭은 해당 종목 agent 생성 후. 배드민턴 회차 한 판은 §21. 3x3·코트 2·모임 기본값 4v4 토글은 안 함.

## 16. 홈·대회 화면 영향

- **잠금(A):** 홈 H1 · Primary=`대회 만들기`. `내 모임`은 섹션. 탭 추가 없음. B·C 기각. [`docs/SCORE-UP-제품방향-비교.md`](SCORE-UP-제품방향-비교.md)
- **탭 추가 없음.** `내 모임`은 홈 섹션. 탭하면 `/club/[id]` 개요.
- `내 모임`: `completed` 아닌 모임 2~5개. 한 줄 다음 일: 다음 회차 날짜 + 내 투표(`참석`/`불참`/`미정`/`없음`). 빈 홈에서는 섹션 숨김(A).
- 진행 중: 오늘 회차가 `voting`/`confirming`이면 경기 카드와 같이 둘 수 있음. 라운드 자리 `회차`. 라이브 점수는 회차 경기가 `in_progress`일 때만.
- 대회 만들기: **`이 모임의 대회로 열기` 없음** (이번 mock). 대회는 지금처럼 독립 생성. 그 대회 결과는 모임 랭킹에 안 들어감. 연결은 API 후.
- 빠른 친선: 유지. 카피를 모임으로 바꾸지 않음.

### 21.4 회차 한 판 (농구 매칭과 섞지 말 것)

```text
투표 마감 → confirming
 → 한 판 열기 (단식 | 복식)
 → 운영자가 출전 고름 (단식 2명 / 복식 홈2·어웨이2)
 → Match 1개 (`sessionId`, 기존 배드민턴 보드)
 → 결과 → 모임 전적
```

| 입력 | 기본 |
| --- | --- |
| 포맷 | 회차 `format`: `singles` / `doubles`(기본) |
| 최소 후보 | 단식 2 · 복식 4 |
| 코트 | 1 |
| 초과 | 대기만 표시. 자동 로테이션 없음 |
| 확정 | 운영자. 시스템이 짝을 정하지 않음 (1차 수동) |

농구 `5v5`/`4v4` 버튼·카피를 이 화면에 두지 않는다. 후보 미달 카피만 21.6.

### 21.5 화면

기존 모임 스택 재사용. 새 탭 없음.

- 모임 만들기: 종목 타일 **배드민턴** 활성 (배구/탁구 잠금)
- 회차 상세 `confirming`: **한 판 열기** (단식/복식). 팀 나누기(5v5) 없음
- 출전: `/club/[id]/sessions/[sid]/bout`. 확정 후 보드 (lineup 스킵)
- 보드: `/match/[id]/badminton` 재사용. 새 보드 없음
- 급수·도전·결과 넣기: 농구 모임과 같은 경로

와이어: `docs/SCORE-UP-모임-상세.md` §4.7b.

### 21.6 카피

| 위치 | 문구 |
| --- | --- |
| 한 판 | 한 판 열기 |
| 단식 | 단식 |
| 복식 | 복식 |
| 미달 단식 | 단식은 참석 2명이 필요합니다. 게스트를 추가하세요 |
| 미달 복식 | 복식은 참석 4명이 필요합니다. 게스트를 추가하세요 |
| 확정 | 한 판을 만들고 보드로 갈까요? |

쓰지 말 것: `5대5`, `4대4`, `출석`, `RSVP`, `코트 호출`, `대진 생성`(주간 순환처럼), `남복 자동`, `A조`, `회비`, `셔틀`.

### 21.7 데이터 (예약)

```text
Session.format   농구: 5v5 | 4v4
                 배드민턴: singles | doubles   (기본 doubles)
```

Match는 기존. 복식은 보드 이름만(슬래시). 위치·서브 순서 필드 없음.

### 21.8 오픈 이슈 (배드민턴 모임만)

1. 복식 **4명** 결과 넣기 — 1차 안 함. 급수 칸이 두 사람
2. 남복/여복/혼복 **필터**(자동 아님) — 1차 안 함
3. 한 회차에 한 판이 아니라 **여러 판** 연속 — 1차 안 함. Match 여러 개는 2차 후보
4. 민턴 A~D 라벨을 초중상에 덧붙일지 — **안 함** (1차)
